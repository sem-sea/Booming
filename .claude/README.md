# `.claude/` — GEO/AEO agent infrastructure

This directory configures Claude Code to self-enforce the May 2026 Bible during content work on the Booming Venture repo. Nothing here ships to production; it only changes how Claude Code behaves in this checkout.

## Contents

```
.claude/
├── README.md                          ← you are here
├── settings.json                      ← wires the post-edit hook
├── commands/
│   ├── geo-audit.md                   ← /geo-audit <slug|URL|file>
│   ├── optimize-passage.md            ← /optimize-passage <file + heading>
│   ├── generate-faq.md                ← /generate-faq <slug>
│   ├── add-schema.md                  ← /add-schema <page-type>
│   └── llms-txt.md                    ← /llms-txt
├── skills/
│   ├── geo-writer/SKILL.md            ← invoked when writing/rewriting long-form content
│   ├── schema-builder/SKILL.md        ← invoked when adding/fixing JSON-LD
│   └── citation-finder/SKILL.md       ← invoked when a claim needs a verifiable source
└── hooks/
    └── post-edit-geo-check.sh         ← runs after every Edit / Write / MultiEdit
```

## How to use

### Slash commands

In any Claude Code session in this repo:

```
/geo-audit what-is-ai-marketing
/optimize-passage build-blog-content-geo.py "What is X?"
/generate-faq scale-lead-gen-without-scaling-team
/add-schema /pricing
/llms-txt
```

### Skills

The three skills auto-trigger when the description matches the work. You can also invoke them explicitly:

- `geo-writer` — when writing/rewriting any post body, pattern, landing-page copy.
- `schema-builder` — when adding/fixing JSON-LD in `inc/seo.php`.
- `citation-finder` — when a claim needs a primary source.

### Hook

`post-edit-geo-check.sh` fires after every `Edit` / `Write` / `MultiEdit` on:

- `build-blog-content-geo.py` (and the legacy `build-blog-content.py`)
- `wp-content/themes/booming-venture/patterns/*.php`
- `wp-content/themes/booming-venture/templates/*.html`
- `wp-content/themes/booming-venture/import/booming-venture-content.xml`

It checks for:

1. Banned AI-tell phrases (delve / harness / leverage / "in today's fast-paced" / "ever-evolving" / etc.)
2. Em-dashes or en-dashes
3. The "It's not just X, it's Y" construction
4. Per-post structural counts (question-shaped H2s, answer capsules, FAQ blocks) when editing the builder or WXR

The hook is **advisory** (exit 0). It never blocks an edit. The point is to surface drift fast.

## Adding to it

When the Bible updates or new GEO best practices emerge:

1. Update the relevant skill `SKILL.md` first (description + rules)
2. Update the hook script if the new rule is mechanically detectable
3. Add a slash command if the rule deserves a one-shot operation

## Provenance

Built against the Claude Code GEO/AEO Implementation Bible (May 2026 Guide). Project-specific extensions:

- WordPress FSE assumed (SSR by default, so step 2 of the audit is usually trivial)
- The builder lives at `build-blog-content-geo.py`; rebuilds the WXR at `wp-content/themes/booming-venture/import/booming-venture-content.xml`
- Schema is generated by `wp-content/themes/booming-venture/inc/seo.php`; do not hand-author
- Robots.txt, llms.txt, IndexNow live in `wp-content/themes/booming-venture/inc/geo.php`
